# Notenverwaltung 1.7.0

**Version vom 16.10.2026.** Diese Fassung ergänzt einen separat zu sichernden
Offline-Wiederherstellungscode für lokale Daten und neue verschlüsselte Backups.

## Änderungen

- Neue Einrichtung mit Passwort und Wiederherstellungscode: Code sichern oder
  drucken, anschließend vollständig erneut eingeben. Erst die Bestätigung
  übernimmt den neuen Schutz.
- Bestehende zugängliche Bestände können den Code unter **Einstellungen →
  Sicherheit** freiwillig nachrüsten; das bisherige Passwort bleibt bis dahin nutzbar.
- **Zugang wiederherstellen** öffnet den lokalen Bestand oder eine passende
  Backup-Datei per Code und richtet ein neues Passwort und einen neuen
  bestätigten Code ein. Das Ersetzen vorhandener Daten aus einer Datei verlangt
  eine ausdrückliche Bestätigung.
- **Code prüfen**, **Code ersetzen** und **Passwort ändern** sind über die
  Sicherheitseinstellungen erreichbar. Passwortwechsel und Codeersatz erneuern
  den Code; normaler Backup-Import behält den lokalen Schutz.
- Selbstenthaltendes V2-Format mit getrennten verschlüsselten Zugängen für
  Passwort und Code. Speicherübergänge prüfen Sitzung, Fensterbesitz, Generation
  und unveränderten Ausgangsbestand; Journal, Rücklesen und verschlüsselte
  Migrationskopie schützen die Übernahme auch bei Teilschreibfehlern.

## Vor dem Umstieg

1. Im bisherigen Fenster ein verschlüsseltes Backup erstellen und die
   heruntergeladene Datei kontrollieren. Die Quellsicherung aufbewahren.
2. Alle Fenster der alten Programmfassung schließen. Das vollständige neue
   Anwendungspaket in einen festen Ordner entpacken und die HTML-Datei öffnen.
3. Den erwarteten Bestand prüfen. Ein anderer Browser, ein anderes Profil oder
   ein anderer Öffnungspfad kann einen getrennten Bestand anzeigen; bei Bedarf
   das Backup bewusst importieren.
4. Einen vorhandenen Bestand bei Bedarf mit dem aktuellen Passwort auf Codezugang
   umstellen. Den Code getrennt von den Backups sicher verwahren und vollständig
   zur Bestätigung erneut eingeben; die angebotene verschlüsselte Alt-Kopie sichern.
5. Nach der Umstellung ein neues Backup erstellen und mit einer kontrollierten
   Wiederherstellungsprobe in einem getrennten Testbestand prüfen.

**V2-Bestände und V2-Backups benötigen Version 1.7.0 oder neuer.** Ältere
HTML-Versionen können sie nicht lesen. Vorhandene Backups ändern sich durch
Nachrüstung, Passwortwechsel oder Codeersatz nicht; sie benötigen weiterhin ihre
damaligen Zugangsdaten. Ein V1-Backup ohne Code bleibt mit dem ursprünglichen
Passwort importierbar. Ein bereits gesperrter Altbestand ohne eingerichteten Code
kann nicht nachträglich mit der neuen Funktion geöffnet werden.

Passwort und Code sind gleichwertige geheime Zugänge. Sind beide verloren,
gibt es keinen Reset, kein Masterpasswort und keinen Support-Zugang. Nach
Passwortwechsel, Codeersatz oder Wiederherstellung neuen Code und neues Backup
sichern. Ein normaler Import bewahrt Passwort, Code und Generation des Zielbestands;
**Zugang wiederherstellen** legt dagegen einen neuen Schutz an.

## Prüfstand und Grenzen

Die vollständige Testsuite der Version 1.7.0 besteht am 16.10.2026 unter Windows
mit Node 26.11.1: 1.482 von 1.482 Tests, keine übersprungen. Ein normaler
temporärer Ordner außerhalb von OneDrive beseitigt die früheren
Dateisystem-Umgebungsfehler; die Schutzprüfungen bleiben unverändert.
Unabhängige Reviews am Implementierungsstand sind dokumentiert.
Der Nutzer hat Nachrüstung und tatsächliche
Wiederherstellung erfolgreich ausprobiert. Browser, Betriebssystem, genaue
Datei/Prüfsumme und Wiederherstellungsvariante wurden nicht genannt; eine
Bestätigung beider Recoveryquellen oder Safari/macOS wird daraus nicht abgeleitet.

Automatisierte Prüfungen ersetzen keine vollständige reale Browserabnahme.
Tatsächlicher Ausdruck, Zielgeräte-Laufzeit und physische Crash-Durabilität
bleiben gesonderte Praxisgrenzen; Tablets und Smartphones sind nicht umfassend
geprüft. Den Umfang beschreibt die beiliegende ABNAHME.md; technische Einzelheiten
stehen im [Implementierungsnachweis](https://github.com/MIBMCG/Notenverwaltung-public/blob/main/docs/quality/password-recovery-verification.md).
